# AKS Newsletter – September 2026

Welcome to the September 2026 edition of the AKS Newsletter.

This month brings **1 feature reaching General Availability** and **6 new Preview announcements**. Here are some of the highlights:

- **Autoscaling for Virtual Machines node pools**, including multi-SKU autoscaling, is now generally available
- **Flex Nodes for AKS** enters public preview
- **Ubuntu 26.04 support in AKS** enters public preview
- **Converting existing clusters to managed system node pools** enters preview

Let's dive in.

---

## ✅ General Availability Announcements

## 🧪 Preview Feature Announcements

* **[Public Preview: Flex Nodes for AKS](https://azure.microsoft.com/en-us/updates/571919/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Flex Nodes introduce a flexible deployment model allowing hybrid and edge infrastructure to seamlessly integrate as worker nodes with an AKS control plane in Azure. This is crucial for teams looking to leverage diverse environments without compromising on the centralized management offered by AKS.

* **[Public Preview: Ubuntu 26.04 support in AKS](https://azure.microsoft.com/en-us/updates/573214/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: With Ubuntu 26.04 support, AKS users can align with the latest LTS releases, ensuring enhanced security and compatibility. This update is vital for maintaining a secure and efficient Kubernetes environment as new features and patches are introduced.

* **[Convert existing clusters to managed system node pools (preview)](https://aka.ms/aks/hobo-conversion?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Existing clusters can be converted in supported regions after registering the required preview feature.

* **[Blue-Green Upgrade (preview)](https://learn.microsoft.com/azure/aks/blue-green-node-pool-upgrade?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Node pools with a blue-green upgrade in progress can now switch safely to the rolling upgrade strategy, giving operators another recovery path during an upgrade.

* **[Cluster Health Monitor (preview)](https://learn.microsoft.com/azure/aks/cluster-health-monitor?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: On-Demand Monitor adds node health checks and remediation in preview. Teams can use it to investigate and address unhealthy nodes without assuming that every issue will be resolved automatically.

* **[AKS Hyperscale Configuration (preview)](https://aka.ms/aks/hyperscale?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: H2, H4, and H8 profiles let teams preprovision control plane capacity for large AI, HPC, and batch workloads. The goal is more predictable API responsiveness and scheduling throughput during scale-out and recovery.

## 🔁 Behavioral Changes

* **[LocalDNS](https://aka.ms/aks/localdns?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Starting with Kubernetes 1.37, LocalDNS is enabled automatically on supported networking configurations. Clusters using bring-your-own CNI, unsupported network policy configurations, or existing custom DNS aren't changed.

* **[HTTP proxy](https://aka.ms/aks/http-proxy?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: New clusters using an HTTP proxy or Custom Certificate Authority reject CA certificate content larger than 35 KB to keep node bootstrap data within platform limits. Existing clusters aren't affected.

* **[Managed namespace](https://learn.microsoft.com/azure/aks/managed-namespaces?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Creating a managed namespace now rejects names beginning with the reserved `kube-` or `aks-istio-` prefixes.

* **[Static Egress Gateway](https://learn.microsoft.com/azure/aks/configure-static-egress-gateway?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: Nodes now deregister from the load balancer before a node-image upgrade reimages them, reducing the risk of interrupted egress traffic.

* **[KMS encryption-at-rest for Kubernetes secrets handled by K8s API with customer managed key](https://learn.microsoft.com/en-us/azure/aks/migrate-key-management-service-platform-managed-key-customer-managed-key?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: AKS now returns a validation error when enabling customer-managed KMS encryption on Kubernetes 1.37 clusters with a versioned Key Vault key ID. Use a versionless key ID instead.

* **[Azure Monitor managed service for Prometheus](https://learn.microsoft.com/azure/azure-monitor/containers/prometheus-metrics-scrape-crd?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09#basic-authentication-and-bearer-tokens)**: On Kubernetes 1.37 and later, ama-metrics uses namespace-scoped access to secrets. Configure access before upgrading if your PodMonitor or ServiceMonitor references Kubernetes secrets for authentication.

* **[Azure Linux with OS Guard retirement](https://learn.microsoft.com/en-us/azure/azure-linux/azure-container-linux-overview?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-09)**: This preview OS option retires on December 10, 2026; AKS will stop publishing images and security patches, then remove existing images on March 10, 2027. Plan a move to Azure Container Linux before scaling or remediation is affected.

## 🧠 Closing Thoughts

September's changes put upgrades and cluster operations in focus. Virtual Machines node pool autoscaling reached GA, while previews added flex nodes, control plane capacity profiles, and new paths for node health checks and upgrades.

Before moving to Kubernetes 1.37, check whether LocalDNS will be enabled in your cluster and whether your Prometheus scrape configurations need namespace-scoped secret access. Teams using Azure Linux with OS Guard should also plan their migration ahead of its December retirement.
