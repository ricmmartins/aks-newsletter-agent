# AKS Newsletter – July 2026

Welcome to the July 2026 edition of the AKS Newsletter.

This month brings **5 features reaching General Availability** and **5 new Preview announcements**. Here are some of the highlights:

- **Encryption in Transit for Azure Files NFS Shares in Azure Kubernetes Service (AKS)** is now generally available
- **Application Routing with Gateway API** is now generally available
- **Artifact Streaming** is now generally available
- **Node Disruption Policy** enters public preview
- **NAT Gateway V2** enters public preview
- **Automatic zone placement** enters public preview

Let's dive in.

---

## ✅ General Availability Announcements

* **[Generally Available: Encryption in Transit for Azure Files NFS Shares in Azure Kubernetes Service (AKS)](https://azure.microsoft.com/en-us/updates/567787/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: AKS now supports Encryption in Transit for Azure Files NFS v4.1 volumes via the Azure File CSI driver. This enhancement is crucial for securing data as it moves between nodes and storage, addressing compliance and security concerns.

* **[Generally Available: Application Routing with Gateway API](https://azure.microsoft.com/en-us/updates/567944/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: The Gateway API for application routing is now generally available, offering a modernized approach to managing ingress routing. This update is significant for teams looking to integrate Kubernetes-native ingress solutions while maintaining compatibility with existing deployments.

* **[Artifact Streaming – now generally available](https://aka.ms/aks/artifact-streaming?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Artifact Streaming is now generally available, providing a more efficient method for handling large container images and artifacts. This feature is essential for optimizing CI/CD pipelines and reducing deployment times in AKS environments.

* **[Secure TLS bootstrapping – now generally available](https://aka.ms/aks/secure-tls-bootstrapping?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Secure TLS bootstrapping is now enabled by default in `westcentralus` and `eastasia`, enhancing the security posture of AKS clusters. This feature simplifies the process of establishing secure communication channels between nodes, critical for maintaining cluster integrity.

* **[Secure Boot – now generally available](https://aka.ms/aks/trusted-launch?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Secure Boot is now supported for AKS clusters using GPUs with Azure Linux OS, providing an additional layer of security by ensuring that only trusted software is executed. This is particularly important for workloads that require high levels of security assurance.

## 🧪 Preview Feature Announcements

* **[Node Disruption Policy (preview)](https://aka.ms/aks/nodedisruptionpolicy?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This feature introduces policies to manage and minimize disruptions in AKS clusters, providing engineers with more control over node availability and maintenance events. It's crucial for maintaining high availability in production environments.

* **[NAT Gateway V2 (preview)](https://learn.microsoft.com/azure/aks/nat-gateway#create-an-aks-cluster-with-a-managed-standardv2-nat-gateway-managednatgatewayv2?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Now available in public preview, this update allows the use of `outboundType: managedNATGateway` with `natGatewayProfile.sku: standardV2`, offering enhanced scalability and performance for outbound traffic management in AKS clusters.

* **[Automatic zone placement (preview)](https://aka.ms/aks/automatic-zonal-placement?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This feature automates the distribution of AKS resources across availability zones, simplifying deployment and enhancing resilience. It's a significant step forward for engineers looking to optimize resource distribution without manual intervention.

* **[Prepared Image Specification (preview)](https://learn.microsoft.com/azure/aks/prepared-image-specification-overview?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This preview feature allows engineers to define and use pre-configured images for AKS nodes, streamlining the deployment process and ensuring consistency across environments. It's particularly beneficial for teams aiming to reduce setup time and configuration errors.

* **[Full caching mode for Ephemeral OS disks (preview)](https://learn.microsoft.com/azure/aks/full-cache-ephemeral-os-disk?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This feature enables full caching for ephemeral OS disks, improving I/O performance and reducing latency for workloads. It's a valuable enhancement for engineers seeking to optimize the performance of their AKS clusters.

## 🔁 Behavioral Changes

* **[Windows best practices](https://aka.ms/aks/windows-best-practices?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This documentation was refreshed with updated guidelines for optimizing Windows workloads on AKS. It emphasizes security, performance, and compatibility, providing essential insights for engineers managing Windows containers.

* **[the preview property enableCustomCATrust will retire](https://github.com/Azure/AKS/issues/5826)**: The enableCustomCATrust preview feature is scheduled for retirement, impacting configurations relying on custom certificate authorities. Engineers need to transition to supported methods to maintain secure communication channels.

* **[Windows Annual Channel retirement](https://aka.ms/aks/windows-annual-channel-retirement?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: The retirement of the Windows Annual Channel in AKS necessitates a shift to the Long-Term Servicing Channel (LTSC) for continued support and updates. This change is crucial for maintaining compliance and receiving security patches.

* **[Flatcar preview retirement](https://aka.ms/aks/flatcar-preview-retirement?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: The Flatcar Container Linux preview is being retired, requiring users to migrate to alternative supported Linux distributions. This transition is important for ensuring ongoing support and compatibility with AKS features.

* **[AKS node image upgrade documentation](https://aka.ms/aks/node-image-upgrade?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Updated to cover the latest procedures and best practices for upgrading AKS node images. This is vital for platform engineers to ensure their clusters are running the most secure and efficient versions available.

### Announcements of upcoming changes and retirements

* **Retirement of enableCustomCATrust**: The preview property `enableCustomCATrust` will retire on September 14, 2026. This change requires immediate attention to update clusters and node pools, removing the property to prevent scaling and certificate update failures.
* **Windows Server Annual Channel Node Pools**: AKS will no longer support creating node pools with Windows Server Annual Channel for Containers. Teams should plan migrations to supported versions to maintain compliance and support.
