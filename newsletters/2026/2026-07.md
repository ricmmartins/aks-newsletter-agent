# AKS Newsletter – July 2026

Welcome to the July 2026 edition of the AKS Newsletter.

This month brings **5 features reaching General Availability** and **5 new Preview announcements**. Here are some of the highlights:

- **Encryption in Transit for Azure Files NFS Shares in Azure Kubernetes Service (AKS)** is now generally available
- **Application Routing with Gateway API** is now generally available
- **Artifact Streaming** is now generally available
- **Node Disruption Policy** enters public preview
- **NAT Gateway V2** enters public preview
- **Automatic zone placement** enters public preview

Let's dive in.

---

## ✅ General Availability Announcements

* **[Generally Available: Encryption in Transit for Azure Files NFS Shares in Azure Kubernetes Service (AKS)](https://azure.microsoft.com/en-us/updates/567787/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: AKS now fully supports Encryption in Transit for Azure Files NFS v4.1 volumes via the Azure File CSI driver. This enhancement is crucial for securing data as it moves between nodes and storage, addressing compliance and security requirements.

* **[Generally Available: Application Routing with Gateway API](https://azure.microsoft.com/en-us/updates/567944/?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: The Gateway API for application routing is now generally available, offering a modern approach to managing ingress routing. This is significant for teams looking to integrate newer Kubernetes standards while maintaining compatibility with existing infrastructure.

* **[Artifact Streaming – now generally available](https://aka.ms/aks/artifact-streaming?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Artifact Streaming is now generally available, providing a streamlined way to manage and deploy container images. This feature enhances CI/CD workflows by reducing the time and complexity involved in artifact distribution.

* **[Secure TLS bootstrapping – now generally available](https://aka.ms/aks/secure-tls-bootstrapping?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Secure TLS bootstrapping is now enabled by default in `westcentralus` and `eastasia`, enhancing the security posture of AKS clusters by ensuring nodes automatically establish secure communications during initialization.

* **[Secure Boot – now generally available](https://aka.ms/aks/trusted-launch?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Secure Boot is now supported for AKS clusters using GPUs with Azure Linux OS, providing an additional layer of security by verifying the integrity of the boot process. This is particularly important for workloads requiring high security assurance.

## 🧪 Preview Feature Announcements

* **[Node Disruption Policy (preview)](https://aka.ms/aks/nodedisruptionpolicy?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This preview feature introduces policies to manage node disruptions, providing engineers with more control over application availability during maintenance events. It is essential for maintaining service reliability in production environments.

* **[NAT Gateway V2 (preview)](https://learn.microsoft.com/azure/aks/nat-gateway#create-an-aks-cluster-with-a-managed-standardv2-nat-gateway-managednatgatewayv2?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Now available in public preview, this feature allows the use of `outboundType: managedNATGateway` with `natGatewayProfile.sku: standardV2`, offering improved scalability and performance for outbound connections in AKS clusters.

* **[Automatic zone placement (preview)](https://aka.ms/aks/automatic-zonal-placement?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This preview feature automates the distribution of nodes across availability zones, enhancing fault tolerance and availability without manual configuration. It's a significant improvement for engineers looking to optimize resource allocation and resilience.

* **[Prepared Image Specification (preview)](https://learn.microsoft.com/azure/aks/prepared-image-specification-overview?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This feature allows users to define and manage custom images for AKS nodes, streamlining the deployment process and ensuring consistency across environments. It is particularly beneficial for teams with specific compliance or configuration requirements.

* **[Full caching mode for Ephemeral OS disks (preview)](https://learn.microsoft.com/azure/aks/full-cache-ephemeral-os-disk?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Now in public preview, this feature enhances performance by enabling full caching for Ephemeral OS disks, reducing latency and improving I/O operations. This is crucial for workloads demanding high-speed data access.

## 🔁 Behavioral Changes

* **[Windows best practices](https://aka.ms/aks/windows-best-practices?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: This documentation was refreshed with updated best practices for running Windows workloads on AKS, focusing on security, performance, and compatibility enhancements. This transition is vital for ensuring ongoing support and leveraging the latest features.

* **[AKS node image upgrade documentation](https://aka.ms/aks/node-image-upgrade?utm_source=aksnewsletter&utm_medium=website&utm_campaign=2026-07)**: Updated to cover new procedures and best practices for upgrading AKS node images, this documentation is critical for maintaining cluster security and performance. ### Announcements of upcoming changes and retirements

* **[Retirement of enableCustomCATrust](https://github.com/Azure/AKS/issues/5826)**: On September 14, 2026, the preview property `enableCustomCATrust` will be retired. This change necessitates updating impacted clusters and node pools to prevent scaling and certificate update failures, emphasizing the importance of proactive configuration management.
