# AKS Newsletter – June 2026

Welcome to the June 2026 edition of the AKS Newsletter.

This month brings **7 features reaching General Availability** and **2 new Preview announcements**. Here are some of the highlights:

- **Generally available: Managed system node pools in AKS Automatic** is now generally available
- **Application Gateway for Containers** is now generally available
- **Ubuntu 22.04 node pools with FIPS 140-3 compliance** is now generally available
- **Anyscale on Azure** enters public preview
- **Application Gateway for Containers – Inference gateway** enters public preview

Let's dive in.

---

## ✅ General Availability Announcements

* **[Generally available: Managed system node pools in AKS Automatic](https://azure.microsoft.com/en-us/updates/562919/)**: Managed system node pools are now GA, simplifying the operational overhead of scaling, patching, and maintaining system node pools. This feature ensures higher availability and reduced manual intervention for platform teams.

* **[Application Gateway for Containers – now generally available](https://learn.microsoft.com/azure/application-gateway/for-containers/overview)**: Application Gateway for Containers is now GA, offering a fully managed Layer 7 load balancing solution tailored for containerized workloads. This enables advanced traffic routing, SSL termination, and DDoS protection for AKS environments.

* **[Ubuntu 22.04 node pools with FIPS 140-3 compliance – now generally available](https://aka.ms/aks/fips)**: Ubuntu 22.04 node pools with FIPS 140-3 compliance are now GA, providing enhanced security for workloads requiring strict cryptographic standards. This is critical for regulated industries and compliance-focused deployments.

* **[Managed GPUs – now generally available](https://learn.microsoft.com/azure/aks/gpu-cluster)**: Managed GPUs are now GA, enabling seamless integration of GPU resources into AKS clusters. This is a game-changer for teams running ML workloads, AI inference, or other GPU-intensive applications, as it simplifies provisioning and scaling.

* **[Confidential VMs (CVM) – now generally available](https://aka.ms/aks/cvm)**: Confidential VMs are now GA with Azure Linux, offering hardware-based encryption for data in use. This feature is essential for workloads requiring high levels of data privacy and security, such as financial or healthcare applications.

* **[Windows Server 2025 – now generally available](https://aka.ms/aks/upgrade-windows-os-version)**: Windows Server 2025 is now GA for AKS, ensuring compatibility with the latest Windows Server features. This update is crucial for teams modernizing Windows-based applications while maintaining supportability.

* **[Azure Container Linux – now generally available](https://learn.microsoft.com/azure/azure-linux/azure-container-linux-overview)**: Azure Container Linux is now GA as an OS option for AKS starting with version 1.34. This lightweight, secure, and optimized OS is designed specifically for containerized workloads, offering improved performance and streamlined updates.

## 🧪 Preview Feature Announcements

* **[Public Preview: Anyscale on Azure](https://azure.microsoft.com/en-us/updates/562934/)**: Introduces a managed Ray platform tailored for running large-scale Python-based machine learning workloads. This preview empowers engineers to scale AI applications efficiently while maintaining granular control over performance and resource utilization.

* **[Public Preview: Application Gateway for Containers – Inference gateway](https://azure.microsoft.com/en-us/updates/566516/)**: Expands Application Gateway for Containers with AI-focused ingress capabilities, enabling seamless integration of inference workloads. Ideal for teams deploying containerized AI models that require low-latency, scalable, and secure access paths.

## 🔁 Behavioral Changes

* **[AKS Automatic](https://learn.microsoft.com/azure/aks/automatic/overview)**: Clusters running Kubernetes 1.36 or later can now disable the default application routing add-on with Gateway API to use the Istio-based service mesh add-on with Istio CNI. This flexibility allows engineers to adopt Istio CNI seamlessly during or after cluster creation.

* **[Deployment Safeguards](https://learn.microsoft.com/azure/aks/deployment-safeguards)**: Enforce mode now applies default resource requests to DaemonSets and Jobs when missing, in addition to Deployments and StatefulSets. This ensures resource predictability and stability across workloads.

* **[Custom Prometheus Metric Scraping](https://learn.microsoft.com/azure/azure-monitor/containers/prometheus-metrics-scrape-configuration)**: Enabled for AKS Automatic clusters using managed system node pools, along with log collection. This enhances observability for platform engineers managing complex workloads.

* **[Azure CNI Static Block Allocation](https://learn.microsoft.com/azure/aks/configure-azure-cni-static-block-allocation)**: VnetScale clusters no longer require explicit pod CIDR configuration. This simplifies network setup and reduces configuration overhead.

* **[Windows gMSA](https://learn.microsoft.com/azure/aks/use-group-managed-service-accounts)**: Now validates CoreDNS conflicts, ensuring smoother integration of group-managed service accounts in Windows-based AKS clusters.

* **[Pod Sandboxing (Kata)](https://learn.microsoft.com/azure/aks/use-pod-sandboxing)**: Now supports workload runtime node pools, expanding the use cases for secure and isolated workloads in AKS.

* **[Pod Sandboxing (Kata)](https://learn.microsoft.com/azure/aks/use-pod-sandboxing)**: Node pools using `Standard_DadsV7`-series VM sizes are now supported, removing previous nested-virtualization validation restrictions.

* **[AKS Automatic](https://learn.microsoft.com/azure/aks/automatic/overview)**: Managed system node pools are now aligned with the AKS Base SKU, providing a consistent and optimized infrastructure experience.

* **[Windows Server 2022](https://aka.ms/aks/upgrade-windows-os-version)**: Retirement has been extended, giving teams more time to plan and execute migrations without disruption.

* **[Istio CNI](https://learn.microsoft.com/azure/aks/istio-cni)**: Now integrates seamlessly with the AKS ecosystem, enabling advanced networking features for service mesh deployments without requiring sidecar injection.

* **[Istio-Based Service Mesh Add-On](https://learn.microsoft.com/en-us/azure/aks/istio-support-policy#service-mesh-add-on-release-calendar)**: Deprecated in favor of more modern and flexible service mesh solutions. Teams should plan migrations to supported alternatives.

* **[Migration Guide](https://learn.microsoft.com/azure/aks/upgrade-windows-os)**: Updated with step-by-step instructions for transitioning workloads from deprecated Windows Server versions to supported ones. Essential for maintaining compliance and stability.

* **[Windows Server 2019 Retirement GitHub](https://aka.ms/aks/ws2019-retirement-github)**: Centralized repository with resources and timelines for Windows Server 2019 retirement. A must-visit for teams planning their upgrade strategy.

* **[Azure Container Linux for AKS](https://learn.microsoft.com/azure/azure-linux/tutorial-migrate-azure-container-linux-aks)**: Introduced as a migration path for teams moving from Ubuntu-based nodes to Azure Container Linux. This ensures a smoother transition to a Microsoft-maintained OS.

* **[Managed System Node Pools](https://aka.ms/aks/managedsystemnodepools)**: Now generally available for AKS Automatic clusters, simplifying operations with automated lifecycle management and enhanced reliability.

* **[LocalDNS](https://learn.microsoft.com/azure/aks/localdns-custom)**: Default mode set to `Required`, including for new node pools in existing Automatic clusters. This change improves DNS resolution performance and reliability.

* **[Edit the `excludedNamespaces` Field for Deployment Safeguards](https://learn.microsoft.com/azure/aks/deployment-safeguards#excluding-namespaces)**: Allows fine-grained control over which namespaces are affected by deployment safeguards in Automatic clusters, improving policy flexibility.

* **[Deployment Safeguards](https://learn.microsoft.com/azure/aks/deployment-safeguards)**: Enforce mode with Pod Security Standards set to Baseline now permits pods on Automatic clusters to read `/var/log` and `/hostfs` hostPath volumes (read-only). This supports log exporter scenarios without compromising security.

* **[Upstream Deprecation of Service ExternalIPs](https://kubernetes.io/blog/2026/05/14/kubernetes-v1-36-deprecation-and-removal-of-service-externalips/)**: Kubernetes has deprecated the use of Service externalIPs starting with version 1.36. Platform engineers should evaluate alternative approaches for exposing services externally.
